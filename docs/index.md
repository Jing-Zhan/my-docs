## 为什么要做这个站

我平时把笔记散落在本地 Markdown 文件里，写的时候很顺手，分享的时候却很麻烦：别人要么拿不到文件，要么拿到一堆散落的 `.md`，还得自己装工具才能看。这个站想解决的问题只有一个——**让写好的 Markdown 变成别人点开链接就能读的网页，而且我只需要执行一次 `git push`**。

所以这个站点没有数据库、没有后端服务，全部内容都是构建阶段就生成好的静态 HTML。我能改的只有 `docs/` 里的 Markdown，其余事情交给工具链自动完成。

## 一次典型的发布流程

日常维护只有三步：改文件、本地看一眼、推上去。

```bash
# 1. 修改文档
vim docs/index.md

# 2. 本地预览，确认导航与样式没问题
python -m mkdocs serve

# 3. 提交并推送，剩下的交给 GitHub Actions
git add docs/index.md
git commit -m "更新首页说明"
git push origin main
```

推送之后不需要登录服务器、不需要手动上传 `site/` 目录，也不需要点任何部署按钮。工作流会自己检出源码、装依赖、构建并发布，几十秒后线上页面就是新内容。

## 这个站点的三条设计取舍

1. **只信源码，不提交产物。** `site/` 完全由构建产生，已写进 `.gitignore`。仓库里只有 Markdown 和配置，历史记录干净，也不会出现“产物比源码还旧”的情况。
2. **构建严格模式。** 本地和 CI 都用 `mkdocs build --strict`，把警告当错误处理。这样断链、拼错的 `nav`、缺失的页面在本地就会暴露，不会等到线上才发现。
3. **部署交给官方 Actions。** 使用 `actions/upload-pages-artifact` + `actions/deploy-pages`，权限在工作流里显式声明，不依赖 `gh-pages` 分支，也不需要额外的令牌。
